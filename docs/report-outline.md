# هيكل تقرير المشروع

هاد هيكل مقترح للتقرير. تحت كل فصل في أفكار عن شو بينكتب فيه. التقرير لازم ينكتب بكلامك إنت.

## 1. المقدمة
- المشكلة: مراكز تعليمية كتير بتسجّل الطلاب والحضور والعلامات على الورق أو بملفات Excel منفصلة.
- الهدف: نظام واحد بيجمع الطالب والمدرّس والإدارة.
- النطاق: شو موجود بالنظام وشو مش موجود، متل الدفع الإلكتروني والحصص الأونلاين المباشرة.

## 2. الدراسة والتحليل
- المستخدمين وصلاحيات كل واحد منهم.
- المتطلبات الوظيفية: التسجيل، الدروس، الحضور، الواجبات، لوحة التحكم.
- المتطلبات غير الوظيفية: لغتين، شغل على الموبايل، صلاحيات، حماية الملفات.
- مخططات Use Case: واحد للطالب، وواحد للمدرّس، وواحد للإدارة.
- مقارنة مع أنظمة موجودة متل Moodle و Google Classroom: شو أخدنا منها، وليش عملنا نظام أبسط.

## 3. التصميم
- معمارية MVC بـ Laravel: شو بيعمل الـ Route والـ Controller والـ Model والـ View.
- قاعدة البيانات: مخطط ERD من `docs/database.md`، وشرح ليش كل جدول موجود.
- تصميم الواجهات: الألوان، الخطوط، الـ design system، وصور الآرت بورد.

## 4. التنفيذ
- أهم الأجزاء بالكود، مع مقاطع قصيرة:
  - التسجيل بكورس وشروطه (`Admin/CourseController@enroll`)
  - تسجيل الحضور بـ `updateOrCreate` (`Teach/AttendanceController@store`)
  - التسليم والتصحيح وقفل الواجب بعد التصحيح (`StudentCourseController@submit`)
  - التحقق إنه المدرّس هو صاحب الكورس (`Teach/Controller@checkCourse`)
- الصلاحيات: Roles و Abilities و Middleware.
- اللغتين والوضع الليلي.

## 5. الاختبار
- الاختبارات الآلية: جدول بأسماء الاختبارات الـ 28 وشو بيفحص كل واحد.
- الاختبار اليدوي: سيناريو كامل من حساب طالب ومن حساب مدرّس.

## 6. الخاتمة والتطوير المستقبلي
- شو تحقق من الأهداف.
- أفكار للتطوير: إشعارات بالإيميل، تقارير للإدارة، جدول أسبوعي كامل، تطبيق موبايل يستعمل الـ API.
